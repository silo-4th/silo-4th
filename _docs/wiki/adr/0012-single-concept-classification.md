# 0012. 질문 하나에는 개념 하나만 연결하고, 분류 프롬프트에 개념별 한 줄 정리를 붙인다

- 상태: 확정
- 결정 날짜: 2026-11-09
- 결정한 사람: 개발자
- 관련 문서: [0008. 질문 개념 분류와 요약](0008-question-concept-summary.md), [질문 개념 분류와 요약 설계](../question-concepts-summary.md), Linear [4-95](https://linear.app/silo0/issue/4-95), Linear [4-97](https://linear.app/silo0/issue/4-97)

## 상황

ADR 0008은 AI가 돌려준 개념 ID 가운데 목록에 있는 것을 모두 `question_concepts`에 남겼다. 2026-11-06에 PO가 질문 하나에는 가장 연관 있는 개념 하나만 붙이기로 정했다. 꺼내 먹기는 이 연결로 질문한 절을 센다. 질문 하나가 절 여러 개를 차지하면 묻지 않은 절까지 질문한 절이 되고, 넘어간 절과 질문한 절의 비교가 흐려진다. Linear 4-95 본문에 근거가 있다.

결정 시점에 확인한 사실은 다음과 같다. 근거는 평가 저장소 `silo-4th-ai-evals`의 `classify/records/2026-11-06-single-concept.md`다.

- 질문 106개로 잰 결과, 지금 프롬프트는 일치 76, 부분 일치 26이었다. "개념은 최대 하나만 고른다"는 지시와 개념별 한 줄 정리를 넣으면 두 번 모두 일치 101, 부분 일치 1이었다.
- 응답을 `conceptId` 하나로 받고 `null`을 허용하면 같은 문항의 결과가 실행마다 달라졌다. 배열로 받은 버전은 두 번의 결과가 문항 단위까지 같았다.
- 지시를 넣어도 한 문항에서는 두 번 모두 개념 두 개를 골랐다.
- 질문 1,000건당 비용은 $0.12에서 $0.30으로 늘고, 평균 응답 시간은 1.1초에서 1.4초 사이로 그대로였다.
- `concepts` 테이블에는 한 줄 정리를 넣을 컬럼이 없다. 한 줄 정리의 원본은 단원 본문의 "개념 한눈에 보기" 표다.

## 결정

1. 분류 프롬프트에 "개념은 최대 하나만 고르고, 여러 개념에 걸치면 가장 직접 묻는 개념을 고른다"를 넣는다. 문구는 평가 저장소 `classify/prompts/single-notes.json`의 `system` 값을 그대로 쓴다.
2. 응답 형식은 `conceptIds` 배열로 둔다.
3. 저장할 때는 개념 목록에 있는 ID만 남기고 중복을 버린 뒤, 그 가운데 첫 번째 하나만 `question_concepts`에 넣는다. 테이블은 바꾸지 않는다. TC-180
4. 개념 목록은 한 줄에 `ID: 이름 - 한 줄 정리`로 넘긴다. 한 줄 정리는 `lib/llm/concept-notes.ts`에 개념 ID별 상수로 둔다. 한 줄 정리가 없는 개념은 `ID: 이름`만 넘긴다.
5. 이미 저장된 질문은 다시 분류하지 않는다.

## 검토한 대안

| 대안 | 장점 | 단점 | 택하지 않은 이유 |
| --- | --- | --- | --- |
| 응답을 `conceptId` 하나로 받는다 | 개념이 둘 이상 올 수 없다 | `null`을 허용하면 실행마다 결과가 흔들렸다 | 측정에서 배열 버전이 더 안정적이었다 |
| `concepts`에 한 줄 정리 컬럼을 더한다 | 개념과 정리가 한 행에 있어 따로 놀지 않는다 | 스키마와 마이그레이션이 바뀌고, 같은 때 진행하는 꺼내 먹기 작업과 스키마 순서를 맞춰야 한다 | 4-95는 테이블을 바꾸지 않기로 했고, 개념 24개는 자주 바뀌지 않는다 |
| 단원 본문의 "개념 한눈에 보기" 표를 읽는다 | 원본이 하나로 남는다 | 질문마다 단원 본문 전체를 읽거나 따로 캐시해야 하고, 표의 개념 이름과 `concepts.title`이 같다는 가정에 기대야 한다 | 분류는 모든 질문의 첫 글자 앞에서 돈다 |
| `question_concepts.question_id`에 유일 제약을 건다 | DB가 개념 하나를 보장한다 | 이미 개념이 여러 개 붙은 질문이 있어 정리 마이그레이션이 먼저 필요하다 | 4-95는 테이블을 바꾸지 않고 기존 데이터도 다시 분류하지 않기로 했다 |

## 결과

- 이 ADR은 PO가 정한 "질문 하나에 개념 하나"를 어떻게 구현할지를 적는다.
- 새 질문은 `question_concepts`에 많아야 한 줄이 남는다. 꺼내 먹기의 질문한 절 조회와 퀴즈 생성의 질문 개념 조회는 쿼리를 바꾸지 않아도 된다.
- 과거 요약도 저장한 개념 하나로 찾는다. AI가 둘을 고르면 두 번째 개념의 과거 요약은 넘기지 않는다. 4-95는 과거 요약 찾기 코드를 바꾸지 않기로 했다.
- 4-95 이전에 저장된 질문은 개념이 여러 개 붙은 채 남는다. 이런 질문을 다시 시도하면 연결된 개념을 모두 써서 과거 요약을 찾는다.
- 개념이나 단원 본문의 "개념 한눈에 보기" 표가 바뀌면 `lib/llm/concept-notes.ts`도 함께 고쳐야 한다. 고치지 않으면 그 개념은 이름만으로 분류된다.
- 분류 입력이 질문당 평균 926토큰에서 2,709토큰으로 는다.
- 평가 하네스는 서비스 코드를 부르지 않으므로, 평가 저장소의 `prompts/baseline.json`도 이 프롬프트로 고쳐야 비교가 맞다.

## 다시 검토할 조건

- 개념 수가 늘거나 단원이 더해져 한 줄 정리를 손으로 맞추기 어려워지면 `concepts` 컬럼으로 옮긴다.
- 4-97에서 정답을 검수한 뒤 다시 잰 숫자가 일치 101에 못 미치면 프롬프트를 다시 본다.
- 개념이 여러 개 붙은 옛 질문이 꺼내 먹기 결과를 눈에 띄게 흐리면 정리 마이그레이션과 유일 제약을 검토한다.

# 0010. 서술형 퀴즈 채점은 Haiku 5.5로 서버에서 하고, 실패하면 채점 없이 저장한다

- 상태: 확정
- 결정 날짜: 2026-11-05, 2026-11-07 결정 3, 4, 5 수정
- 결정한 사람: 개발자
- 관련 문서: [0007. 질문 답변 AI 모델](0007-ai-model.md), [0008. 질문 개념 분류와 요약](0008-question-concept-summary.md), [퀴즈 스키마 초안](../../output/2026-11-05-quiz-schema.md), Linear [4-88](https://linear.app/silo0/issue/4-88), [4-75](https://linear.app/silo0/issue/4-75)

## 상황

4-88은 학습자가 푼 퀴즈를 채점해 `quiz_attempts`에 남긴다. 객관식과 빈칸은 정답과 비교하면 되지만, 서술형은 학습자의 설명을 모범 답과 핵심 요소에 비추어 판단해야 해서 AI가 채점한다. 근거는 4-88 본문 "정한 것"이다.

결정 시점에 확인한 사실은 다음과 같다.

- 4-89 흐름은 확신도를 고른 뒤 채점 결과를 기다렸다가 해설을 보여 준다. 채점 시간만큼 학습자가 기다린다.
- 루트 `CLAUDE.md`는 모델 ID를 `env.ANTHROPIC_MODEL`과 `env.ANTHROPIC_UTILITY_MODEL`로만 읽게 하고, 각 변수의 쓰임을 0007과 0008로 정해 두었다. 서술형 채점은 두 ADR 어디에도 없다.
- 0008의 분류는 같은 유틸리티 모델로 JSON 스키마 응답을 받고 10초 안에 끝나지 않으면 끊는다. 근거는 `lib/llm/tagging.ts`다.

## 결정

1. 서술형 채점은 `env.ANTHROPIC_UTILITY_MODEL`의 Claude Haiku 5.5로 부른다. 4-80 프롬프트 시험 결과로 바뀔 수 있다. 퀴즈 생성에 `env.ANTHROPIC_MODEL`을 쓰기로 한 것도 같은 날 함께 정했지만, 근거와 구현은 4-87이 맡는다.
2. 채점은 서버가 한다. 풀이 저장 API가 세 포맷을 모두 채점하고, 화면이 보낸 채점 결과는 쓰지 않는다.
3. AI는 `correct`와 `wrong` 가운데 하나만 돌려주고, 서버는 이를 객관식, 빈칸과 같은 `is_correct`에 저장한다. 판정 근거는 받지 않고, 학습자는 문제의 해설을 본다. 프롬프트에 문항, 힌트, 해설, 모범 답, 핵심 요소, 학습자 설명을 넣고, 학습자 설명 안의 지시는 따르지 않게 한다.
4. 채점은 10초 안에 끝나지 않으면 끊는다. 실패하면 풀이는 `is_correct`를 비운 채 저장하고, 응답에 채점하지 못했다는 표시와 모범 답, 해설을 담는다. 같은 풀이 ID가 다시 와도 다시 채점하지 않는다.
5. 서술형에서 잘 모르겠어요를 누르면 AI를 부르지 않고, 확신도 `guess`와 `is_correct` false로 저장해 틀린 풀이와 같은 응답을 준다.

### 2026-11-07 수정

4-87에서 결정 3, 4, 5를 고쳤다. 처음에는 `partial` 판정과 근거를 `grading`, `grading_reason`에 따로 남기고, 잘 모르겠어요는 `dont_know`로 표시해 확신도를 비웠다. 지표와 화면이 포맷마다 다른 컬럼을 읽어야 해서, 세 포맷 모두 `is_correct`와 확신도 하나로 맞췄다. 근거는 노션 TC-104, TC-105와 4-87 PR 나누기 결정이다. 코드는 4-87 PR 1에서 이 컬럼들을 읽고 쓰지 않게 했고, 컬럼 삭제와 기존 데이터 옮기기는 결정 7을 따라 다음 마이그레이션 PR에서 한다. 기존 `partial`은 틀림으로 옮긴다. 4-87 마이그레이션 `0006_quiz_grading_cleanup`에서 옮기고 지웠다. `dont_know` 풀이는 확신도 `guess`의 틀림으로 옮겼다.

## 검토한 대안

| 대안 | 장점 | 단점 | 택하지 않은 이유 |
| --- | --- | --- | --- |
| 서술형도 답변과 같은 Sonnet 5.5로 채점한다 | 판정이 더 정확할 수 있다 | 학습자가 기다리는 시간과 비용이 늘어난다 | 채점은 짧은 분류에 가까워 Haiku의 쓰임에 맞는다. 4-80 결과로 다시 본다 |
| 채점이 실패하면 풀이를 저장하지 않고 실패를 돌려준다 | 채점 결과 없는 행이 생기지 않는다 | 학습자가 다시 풀거나 기다려야 하고, 풀이 기록이 빠진다 | 기록을 빠짐없이 남기는 것이 이 서비스의 핵심 요구다 |
| 같은 풀이 ID가 다시 오면 채점을 다시 시도한다 | 일시적인 실패를 메울 수 있다 | 같은 풀이의 결과가 요청마다 달라지고, 저장한 행을 나중에 고치는 경로가 생긴다 | 채점 실패 응답은 이미 화면에 도착한 것이라 다시 보낼 일이 드물다 |

## 결과

- 서술형 풀이도 학습자를 오래 기다리게 하지 않고 기록이 남는다. 가장 늦을 때 10초를 기다린다.
- `is_correct`가 빈 서술형 풀이가 생길 수 있다. 지표를 낼 때 채점하지 못한 풀이를 따로 센다.
- 일부만 맞게 쓴 설명도 틀림이 된다. 4-80 시험에서 너무 엄하게 채점하면 프롬프트를 다시 본다.
- 루트 `CLAUDE.md`와 `dev-rules.md`의 모델 규칙에 서술형 채점을 더했다.
- 채점 AI의 JSON 호출은 분류, 요약과 같은 코드를 쓰도록 `lib/llm/ask-json.ts`로 옮겼다.
- 10초는 추정이다. 구현 뒤 실제 응답 시간을 재서 `lib/llm/grading.ts`의 `GRADING_TIMEOUT_MS`를 조정한다. 테스트는 이 값을 읽어 쓰므로 값을 바꿔도 고치지 않는다.

## 다시 검토할 조건

- 4-80 프롬프트 시험에서 Haiku의 채점이 모범 답과 자주 어긋나면 채점 모델을 바꾼다.
- 운영에서 채점하지 못한 풀이가 눈에 띄게 많으면 제한 시간이나 모델을 다시 본다.

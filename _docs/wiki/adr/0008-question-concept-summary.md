# 0008. 질문 개념 분류와 요약은 Haiku 5.5로 따로 부르고, 실패해도 답을 막지 않는다

- 상태: 확정
- 결정 날짜: 2026-11-04
- 결정한 사람: 개발자
- 관련 문서: [질문 개념 분류와 요약 설계](../question-concepts-summary.md), [0007. 질문 답변 AI 모델](0007-ai-model.md), [0005. Sentry 오류 모니터링](0005-sentry-error-monitoring.md), Linear [4-61](https://linear.app/silo0/issue/4-61), Linear 문서 [05-1 기록 구조 테이블 설계](https://linear.app/silo0/document/05-1-기록-구조-테이블-설계-0c3075a457c4)

## 상황

4-61은 질문을 개념에 연결하고 압축 요약을 남겨, 같은 개념을 다시 물으면 과거 요약을 답에 반영하는 일이다. 05-1은 분류를 답변 전에 따로 부르고, 목록에 없는 개념은 `keywords`로 찾기로 제안했다. 몇 개의 요약을 넘길지, 어떤 모델로 부를지, 실패하면 어떻게 할지는 정하지 않았다. (근거: 05-1 "질문 하나가 저장되는 흐름", "아직 정하지 않은 것" 3, 5번)

결정 시점에 확인한 사실은 다음과 같다.

- 분류는 모든 질문에서 답보다 먼저 돌아서, 분류에 걸리는 시간만큼 첫 글자가 늦어진다.
- ADR 0007은 Haiku 5.5를 공식 설명상 분류, 추출, 라우팅용 모델로 적었다. 가격은 100만 토큰당 입력 $0.10, 출력 $0.50으로 Sonnet 5.5보다 싸다. (근거: [0007](0007-ai-model.md) "검토한 대안")
- 기존 통합 테스트의 Anthropic 목은 `messages.stream`만 바꾸고, TC-35, TC-46, TC-50은 `stream` 호출 횟수를 1번으로 확인한다. 루트 `CLAUDE.md`는 이미 있는 테스트를 고치지 않게 한다. (근거: `app/api/questions/route.integration.test.ts`)
- `concepts`는 아직 비어 있고, 개념 수는 Linear 4-27에서 정한다.

## 결정

1. 분류와 요약은 Claude Haiku 5.5로 부른다. 모델 ID는 새 환경 변수 `ANTHROPIC_UTILITY_MODEL`을 `lib/env.ts`의 `env`로 읽는다. 답변은 0007대로 `env.ANTHROPIC_MODEL`의 Sonnet 5.5를 쓴다.
2. 분류는 답변 전에, 요약은 `done`을 보낸 뒤 Next.js `after`로 부른다. 둘 다 스트리밍하지 않는 호출이다.
3. 분류 후보는 단원과 상관없이 `concepts` 전체다. AI가 돌려준 개념 ID는 목록에 있는 것만 남기고 중복을 버린다. 2026-11-09에 [0012](0012-single-concept-classification.md)로 그 가운데 첫 번째 하나만 저장하기로 바꿨다.
4. 답변 프롬프트에는 같은 학습자가 같은 개념으로 물었던 질문의 요약을 최근 5개까지 넣는다. 개념이 없으면 키워드가 겹치는 질문으로 찾는다. 2026-11-05에 대화 세션이 들어오면서, 지금 대화의 질문은 원문으로 이미 넘기므로 요약에서 빼기로 했다. TC-86
5. 요약은 질문과 답의 핵심을 2~3문장, 300자 이내로 쓴다.
6. 분류나 요약이 실패해도 답은 막지 않는다. 분류는 10초 제한을 두고, 실패하면 과거 요약 없이 답한다. 요약이 실패하면 요약 칸을 비워 두고 질문은 `ok`로 남긴다.

## 검토한 대안

| 대안 | 장점 | 단점 | 택하지 않은 이유 |
| --- | --- | --- | --- |
| 분류와 요약도 답변과 같은 Sonnet 5.5로 부른다 | 환경 변수와 모델 규칙이 바뀌지 않는다 | 질문마다 Sonnet 호출이 세 번이라 비용이 늘고, 분류가 첫 글자를 더 늦춘다 | 분류와 요약은 Haiku가 맡도록 소개된 일이고, 첫 글자 지연이 모든 질문에 붙는다 |
| 분류를 답변 호출 안에서 함께 한다 | 호출이 하나 줄어 지연이 없다 | 분류 결과를 알기 전에 답을 시작하므로 과거 요약을 그 답에 넣을 수 없다 | 05-1이 같은 이유로 따로 부르기로 제안했다 |
| 열려 있던 단원의 개념만 후보로 준다 | 후보가 3~4개로 줄어 분류가 쉽다 | 다른 단원 내용을 물으면 개념 없이 키워드로만 남는다 | 이슈가 개념 전체 가운데 분류하라고 적었고, 목록이 15~20개라 프롬프트 부담이 작다 |
| 과거 요약을 상한 없이 모두 넣는다 | 과거 내용을 빠짐없이 넘긴다 | 질문이 쌓일수록 프롬프트가 길어져 비용과 지연이 늘고, 넓은 키워드가 관련 없는 질문을 끌어온다 | 05-1의 목적은 원문 대신 관련 요약만 넘기는 것이다 |
| 요약을 `done` 전에 끝낸다 | 응답이 끝나면 요약도 저장돼 있다 | 학습자가 요약을 만드는 시간만큼 더 기다린다 | 요약은 다음 질문에서만 쓰여 학습자가 기다릴 이유가 없다 |
| 분류가 실패하면 질문을 `error`로 끝낸다 | 개념 없는 질문이 생기지 않는다 | 답을 받을 수 있는데 분류 때문에 실패한다. 기존 테스트의 목에는 분류 호출이 없어 기존 통합 테스트가 깨진다 | 학습자에게는 답이 우선이다 |

## 결과

- 분류가 성공하면 같은 개념의 과거 요약이 답에 반영되고, `question_concepts`에 "많이 물어본 개념"의 근거가 쌓인다.
- 모든 질문의 첫 글자가 분류 시간만큼 늦어진다. 가장 늦을 때 10초다. 실제 지연은 운영에서 처음 잰다.
- 환경 변수 `ANTHROPIC_UTILITY_MODEL`이 늘어난다. `.env.example`, Vercel 운영 환경, `.env.test.local`에 `claude-haiku-5-5`를 넣어야 한다. 루트 `CLAUDE.md`와 `dev-rules.md`의 모델 ID 규칙도 이 변수를 포함하도록 고쳤다.
- 분류와 요약은 스트리밍하지 않는 호출이라, 기존 테스트의 `stream` 호출 횟수 확인은 그대로 맞다. 기존 목에는 이 호출이 없어 실패 경로로 가고, 실패해도 답을 막지 않으므로 기존 테스트가 통과한다.
- 분류가 실패한 질문은 개념 없이 남는다. 나중에 다시 분류하는 작업은 이번에 만들지 않는다.
- `dev-rules.md`는 "AI가 개념을 고르지 않아 LLM 출력 스키마 규칙이 필요 없다"고 적었다. 이 결정으로 AI가 개념을 고르므로, 출력은 경계에서 걸러 낸다.

## 다시 검토할 조건

- 4-27에서 개념 데이터가 들어온 뒤 분류가 자주 틀리면, 개념 설명 칸을 더하거나 분류 모델을 바꾸는 것을 검토한다.
- 분류 때문에 첫 글자가 눈에 띄게 늦다는 사례가 쌓이면 제한 시간을 줄이거나 분류와 답변의 순서를 다시 본다.
- 과거 요약 5개로 답이 과거 내용에 끌려가거나 부족하면 개수를 조정한다.
